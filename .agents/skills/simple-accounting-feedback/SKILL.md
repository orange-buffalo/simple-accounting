# Verified feedback learning

Follow the human-feedback section of `simple-accounting-delivery`. Distinguish an existing requirement miss from new scope or preference. Inspect the original run before changing its evidence. Call `accounting_learn` once for the feedback batch; every accepted concern needs a disposition and a preventive measure or an explicit reason it does not generalize.

Learning is not a model weight update. Only registry-approved, source-grounded lessons influence future agents. The controller records candidates even when baseline replay already catches the issue, verification fails, or the original evidence is insufficient. Such outcomes must not be presented as proven reviewer improvement.
